# External Integrations

**Analysis Date:** 2026-08-11

## APIs & External Services

**Authentication:**
- Supabase Auth - Email/password login, Google OAuth, password recovery flow
  - SDK/Client: `supabase_flutter: ^2.17.1` (frontend), `pyjwt[crypto]` + `PyJWKClient` (backend JWT verification)
  - Auth: `SUPABASE_URL` (backend, `backend/app/auth.py`), `supabaseUrl`/`supabaseAnonKey` (frontend, `frontend/lib/config/app_config.dart`)
  - Google OAuth on desktop (Linux) uses a system-browser + local loopback callback server: `http://localhost:$_oauthLoopbackPort/callback` (`frontend/lib/screens/login_screen.dart`)
  - Backend never talks to Supabase Auth directly for login — it only verifies tokens the frontend already obtained, via Supabase's public JWKS endpoint (`SUPABASE_URL/auth/v1/.well-known/jwks.json`)
  - Custom branded email templates (confirm/reset/magic link) documented in `docs/supabase-email-templates.md`, intended to be pasted into Supabase project's Auth email template settings (no code integration — manual dashboard config)

No other third-party APIs (payment, analytics, error tracking, email-sending service, etc.) are integrated in code as of this analysis.

## Data Storage

**Databases:**
- PostgreSQL (Supabase-managed) - Production target
  - Connection: `DATABASE_URL` env var (`backend/app/repository/db.py`)
  - Client: SQLAlchemy 2.0 ORM + `psycopg[binary]` driver
  - Not yet connected to a real Supabase project in practice (per README, "hoje roda em SQLite local")
- SQLite - Default/local fallback and test database
  - File: `backend/certfly.db`
  - Used automatically whenever `DATABASE_URL` is unset (local dev, `pytest` suite)
  - Schema created idempotently at app startup via `Base.metadata.create_all(bind=engine)` (`backend/app/main.py`) — no migration tool (e.g. Alembic) present yet

**File Storage:**
- None — local filesystem only (question-bank content lives in `content/*.yaml`, loaded into the DB via `scripts/seed_dev.py`)

**Caching:**
- None (JWKS signing keys are cached in-process by `PyJWKClient` + `functools.lru_cache` on the client factory, `backend/app/auth.py` — not an external cache service)

## Authentication & Identity

**Auth Provider:**
- Supabase Auth (full external identity provider, not custom)
  - Frontend obtains sessions via `supabase_flutter` (`frontend/lib/auth/auth_gateway.dart`): `SupabaseAuthGateway` wraps `Supabase.instance.client.auth` for current session, sign-out, and auth-state-change stream
  - Backend validates the resulting JWT on every request via `get_current_user` FastAPI dependency (`backend/app/auth.py`), extracting `AuthenticatedUser(id, email)` from the token's `sub`/`email` claims
  - Production tokens are ES256, verified against Supabase's JWKS (asymmetric, no shared secret stored server-side)
  - Dev-only path: HS256 tokens signed with a shared `SUPABASE_JWT_SECRET`, generated by `scripts/seed_dev.py`, allow bypassing a real Supabase project entirely for local iteration — this path must never be enabled in production (only `SUPABASE_URL` should be set there)
  - Frontend dev bypass: `AppConfig.devToken` / `DevAuthGateway` skips the Supabase login UI entirely using a pre-signed dev token (`frontend/lib/config/app_config.dart`, `frontend/lib/auth/auth_gateway.dart`)

## Environment Configuration

**Required env vars (backend, see `backend/.env.example`):**
- `DATABASE_URL` (optional — Supabase Postgres connection string; falls back to local SQLite)
- `SUPABASE_URL` (required for real JWT validation via JWKS)
- `SUPABASE_JWT_SECRET` (dev-only; enables local HS256 token validation, must be unset in production)

**Required config (frontend, via `--dart-define`/`--dart-define-from-file=dev.json`):**
- `apiBaseUrl`, `supabaseUrl`, `supabaseAnonKey`, `devToken` (dev-only), `certificationId` — see `frontend/lib/config/app_config.dart`

**Secrets location:**
- Backend: `backend/.env` (gitignored, not committed; `backend/.env.example` documents required keys without real secrets)
- Frontend: `dev.json` (generated locally by `scripts/seed_dev.py`, not committed) supplies dev-only overrides; the Supabase "publishable key" hardcoded as a default in `app_config.dart` is explicitly documented as safe to embed client-side (not a secret)

## Webhooks & Callbacks

**Incoming:**
- None — the FastAPI backend exposes only direct request/response endpoints (`me`, `progress`, `certifications`, `lesson`, `answer`, `lesson_session` routers registered in `backend/app/main.py`, plus `/health`)

**Outgoing:**
- Local OAuth loopback callback only: on Linux desktop, Google sign-in opens the system browser and redirects to `http://localhost:$_oauthLoopbackPort/callback`, which the app's embedded loopback server captures to complete the Supabase OAuth flow (`frontend/lib/screens/login_screen.dart`). This is a local-machine callback, not a publicly reachable webhook.
